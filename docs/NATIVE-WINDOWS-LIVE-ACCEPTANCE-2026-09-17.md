# Native Windows Lab Agent live acceptance — 2026-09-17

This record captures the production-backed acceptance performed on a real RoomGoblin-managed Windows endpoint after the native service package and verified enrollment workflow were merged and deployed.

## Production deployment baseline

The RoomGoblin appliance was updated to exact merge commit `68d56d7cd930184f86d3b6256eddec786d3bb12d`. The deployment completed with backend, maintenance, and host-agent convergence at `1.0.0-alpha.82`.

The deployed Hub served `/lab-agent/native/manifest.json` and all four expected native binaries. The Windows endpoint had previously been migrated from the legacy scheduled-task agent to the native service using the production-served package.

## Reboot persistence acceptance

After a full Windows reboot, the endpoint reported:

- service `RoomGoblinAgent` present and `Running`;
- startup mode `Auto` (installed as delayed automatic by the bootstrap);
- service identity `LocalSystem`;
- executable path `C:\Program Files\RoomGoblin\Agent\RoomGoblinAgent.exe`;
- fresh `native-service-health.json` with transport `native-windows-service`;
- legacy scheduled task `RoomGoblin Agent` still `Disabled`;
- SCM recovery policy preserved with restart delays of 5 seconds, 15 seconds, and 60 seconds and a 24-hour reset period.

This validates native service persistence across reboot without relying on the legacy scheduled task.

## Native self-update acceptance

The endpoint then received the RoomGoblin `update-agent` action from the Lab controller.

Acceptance evidence after the update:

- `RoomGoblinAgent` remained `Running`, automatic, and `LocalSystem`;
- native health refreshed immediately after the update;
- `C:\ProgramData\ClassroomControlHub\native-updates` was updated;
- the installed bootstrap binary changed from the prior production build size (`67,498,433` bytes) to the newly published build size (`67,506,625` bytes), demonstrating that a new native package was actually applied rather than only reconnecting;
- no RoomGoblin-related Application event errors were observed in the immediate post-update window.

This validates the production manifest/download/hash/stage/updater/restart/health-acceptance path on the test endpoint.

## Native uninstall and legacy restoration acceptance

The production bootstrap was then executed with `uninstall`.

Observed result:

- bootstrap returned exit code `0`;
- native `RoomGoblinAgent` service was removed;
- `C:\Program Files\RoomGoblin\Agent` was removed;
- compatibility configuration `C:\ProgramData\ClassroomControlHub\lab-agent.json` was preserved;
- legacy `RoomGoblin Agent` scheduled task was re-enabled and entered `Running` state;
- the task action remained the compatibility PowerShell command using `ClassroomHubAgent.ps1` and the preserved `lab-agent.json`;
- Task Scheduler result `267009` (`0x41301`) was observed while the restored task was actively running, which is consistent with the displayed `Running` state rather than a completed failure code.

This validates the intended rollback/removal contract: native removal restores the legacy compatibility agent when that task still exists and leaves its identity/configuration intact.

Validated on a real endpoint:

## Operational note

Do not interpret Task Scheduler result `267009` (`0x41301`) as a failed legacy restoration when the task state is `Running`; that value indicates the task is currently running. Confirm final connectivity/heartbeat in RoomGoblin before making any rollback conclusion.

Do not remove the legacy PowerShell package yet. It remains the tested fallback until fresh-enrollment acceptance and broader rollout criteria are satisfied.
